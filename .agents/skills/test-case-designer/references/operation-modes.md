# 工作模式

一次任务选择一个主模式。用户请求同时包含多种动作时，先完成只读分析，再按“重组 → 补充 → 校验”的顺序执行；不要把评审自动扩大为修改。

## 新建设计

适用：目标文档为空，或用户要求从需求建立完整用例集。

1. 读取事实来源并形成测试分析。
2. 建立测试条件与风险排序。
3. 选择层级主轴和测试方法。
4. 建立追溯关系后生成用例。
5. 写入、回读并执行全量校验。

退出条件：核心来源和高风险测试条件都有覆盖；待确认项没有被写成确定结论。

## 增量补充

适用：需求发生变化，或已有用例存在明确覆盖缺口。

1. 读取现有树和已有用例标识。
2. 识别变更来源、受影响测试条件和回归范围。
3. 优先更新受影响用例；只有出现新测试目标时才新增用例。
4. 保留未受影响节点、稳定用例 ID、备注和历史关系。
5. 将不再适用的用例标记为废弃或报告给用户；除非用户明确授权，不直接删除。

退出条件：新增、修改、废弃和未受影响范围均可说明；没有通过复制整组用例完成增量。

## 层级重组

适用：用户要求调整分组、简化层级或统一命名。

1. 建立重组前节点清单：节点 ID、标题、父节点和后代用例数。
2. 选定新的分类主轴，生成旧位置到新位置的映射。
3. 只移动或重命名节点，不改变用例步骤、预期、优先级和测试意图。
4. 回读后核对用例数量、ID 集合和归属关系。

退出条件：重组前后用例 ID 集合一致，没有丢失、复制或语义漂移；内容缺口单独报告。

## 只读评审

适用：用户要求 review、检查、分析、找缺口或给建议。

允许：读取文档、运行校验器、统计覆盖、输出问题与建议。

禁止：新增、更新、移动、删除节点，或把建议直接写回文档。

输出按“证据 → 风险 → 建议”组织，并区分：

- 确定性问题：字段缺失、非法枚举、重复标题等可由规则证明的问题。
- 语义问题：覆盖不足、优先级失真、层级不合理等需要事实判断的问题。
- 待确认项：缺少需求或判定依据，暂时不能下结论的问题。

退出条件：评审范围和未读取的事实来源已说明；不存在未经授权的写操作。
